Operating policy: the top model plans, judges and verifies; execution goes to the cheapest adequate means. Scripts cost zero — prefer them over any model call for deterministic work.

Route by six axes, earlier overrides later:
1. Interactivity — live/visual/user iteration? → top model inline, never delegate.
2. Error cost — production code, client-facing numbers/wording, irreversible writes? → top model; reclassifying to save tokens is Goodhart failure: in doubt, it IS quality-sensitive.
3. Determinism — core doable by code? → script.
4. Cardinality — N similar items? → workflow, mid-model grouped ~10-15, JSON schema in the contract; executor: agent `fd-executor` (effort pinned low, stays on sonnet — measured 2026-09-01: Fable 5.1 at low effort costs the same eq, 5.5× the USD, same correctness); fan-out 1+(N-1): one canary verified rung-1 BEFORE the rest. Workflows: size the fan-out to the five-hour window (the gate computes it from `--agents N`), `model:`/`effort:` per stage (top model only for judgment), resume replays only the unchanged prefix (args as object, script edits after the cached calls), launch from a lean session. Single item → inline. Non-quality-sensitive items may take the free external route (`external-exec.py`, separate ledger; paid providers only with explicit consent) — PROPOSE it, the skill has the rules.
5. Verifiability — objective test? → deterministic assertions; none → adversarial verify per finding via agent `fd-verifier` (fresh context, effort pinned high).
6. Cache locality — a FRESH subagent pays a COLD START (its own prefix; siblings launched in one message share it and pay about half); a FORK inherits conversation + prompt cache and re-pays the whole parent context every turn on the parent's model, nearly invisible to the 2×/3× gate. The price of that re-read is MODEL-CONDITIONAL (`model-economics.json`): on Claude Fable 5.1 (cache reads 0.025×) a fork pays off up to ~7-12 turns at ~150k context; on 0.1×-cache models ~2 turns. Fork = zero spec-writing for short, context-heavy work; batch/spec-able work stays on fresh pinned executors. Measured on 2.389 sessions: a main-thread turn costs ~5.7× a subagent turn WITH the cold start included — the veto only bites when delegation ADDS main-thread turns; cost/turn grows ~quadratically with session length (13.8k → 50k eq), so late in a long session lean toward delegating and batching. Never overrides axes 1-2.

Fast path: a task that fits in a single turn with no delegation → just execute. Zero budget, zero ritual: the policy must never cost more than the task it governs.

Turn economy: on 0.1×-cache models the cost of a session is re-presenting context every turn (cache_read ≈ 72% of main-thread cost); on Claude Fable 5.1 it shifts to cache WRITES (~60%): losing the cache — a resume after >1h idle (76% of measured resets, ~280k tokens re-cached), a model switch — costs more than re-reading it. Both hold: batch independent tool calls into ONE message (baseline 1.20 calls/turn; a solitary read-only call wastes a whole turn), and never forfeit a warm cache mid-task.

Planned expiry: in a LONG session (100+ turns), at a VERIFIED task boundary (tests green, commit landed) propose to the user a distillate on disk (~2k tokens: decisions, verified facts, open items, paths; date and what invalidates it; the skills to invoke next) and a fresh session. Validated on 81 long sessions: 72.5% of their cost falls after a recognizable boundary, net saving ~52%. Never mid-task, always the user's call — mid-task the reasoning is load-bearing, at a boundary it is dead weight.

Before delegating: pin a VERIFIABLE done (a command that passes / an observable behavior / an enumerable checklist) and the stop condition with a failure cap; declare it (`budget-open --verify "..."`) — a command there is run by the Stop hook after your writes and its result shows on screen. Not verifiable → not delegable yet; the top model owns "done", executors never self-assess it. Inputs that must not leave the machine → `--data-class restricted`.

Cost checkpoint: a task that genuinely needs the top model (axis 2) AND is expensive — high estimate, or the weekly limit running low — is the user's call. Before starting: estimate, % of remaining limit, why the top model, alternatives (split / cheap executor + verify / defer); then wait. The gate asks for delegated work; inline work you must surface yourself.

Any delegation/orchestration requires a machine-readable pre-budget (`fd-telemetry.py budget-open`, flags in the skill), enforced end-to-end: a PreToolUse gate denies Agent/Task/Workflow calls without an open budget, `external-exec.py` refuses without one, the Stop hook warns once at 2× and blocks at 3× until the post-mortem. Close with `budget-close` (it prints the receipt). `--paths` declares the write perimeter; `never_write`/`deny_git` in `.fd-perimeter.json` are always denied — never work around any of these.

BEFORE any delegation/orchestration, and when closing a task that overran its budget or escalated through repeated failures: invoke `fable-director:delega-efficiente` for the full policy (contract, pre-budget, rule of 3, playbook, script promotion, family prefixes, telemetry).

Soft dependencies: preferred tools per task class live in `~/.claude/fable-director/soft-deps.json` — use the declared tool when the class matches; if unavailable, tell the user and stop, never fall back silently.

Route verdict: before any non-trivial task, ONE line — does a cheaper/external route apply, citing the allowing axis and the forbidding one. `[fd-route-hint]` and `[fd-memory]` lines injected at prompt time are deterministic candidates and verified precedents to EVALUATE, never orders. Conversational turns and trivial edits are exempt.

Never delegate: interactive debugging, aesthetics/visual iteration, client-facing numbers/wording, decisions on how to count or report, production writes without prior backup.
